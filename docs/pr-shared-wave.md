# Общая волна

Вторая часть `SPEC-wave.md` (§3.2), строится поверх `feature/my-wave`: сначала нужно влить его.

## Что сделано
- Кнопка «Общая волна»: треки волн всех согласившихся участников идут по кругу.
- Каждый трек запрашивается токеном того, из чьей волны он пришёл, и фидбек уходит ему же.
- Переключатель «Моя волна участвует», список участников, в плеере — «Общая волна · Аня».
- Закрывший вкладку выпадает через 15 с, вернувшийся — снова в ротации; перезагрузка вкладки его не выбрасывает.
- Дубликаты между волнами отфильтровываются.
- Если участников не осталось, волна ждёт, а не останавливается (D-040).
- Отказ токена или Яндекса у одного участника не мешает остальным.

## Как устроено
Один буфер, порядок пересчитывается по кругу при каждой порции и смене состава (D-044). Выбор следующего трека,
предзагрузка и фидбек не отличаются от одиночной волны.

## Как проверить
```bash
npm run check
npm run e2e
```
На реальных аккаунтах — `docs/manual-qa.md` §6. Нужны два аккаунта с Плюсом.

## Результаты
- Backend и frontend: линтеры, типы и тесты зелёные. E2E локально зелёный, включая общую волну.
- **На настоящем API общая волна не запускалась:** нужен второй аккаунт. Чередование и фидбек проверены на FakeProvider.
- CI запускается при открытии PR и пока не проверен.

## Миграции
Нет: участие и сессии хранятся в JSON `rooms.state`.

## Риски
- **Лимиты и аккаунты.** Запросов больше: у каждого участника своя сессия. Запросы идут только при слушателях.
- **Скромный сервер.** В режиме `AUDIO_MODE=proxy` общая волна с несколькими слушателями может упереться в 1 vCPU
  сервера; в режиме `direct` аудио через сервер не идёт.
