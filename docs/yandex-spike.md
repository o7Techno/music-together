# Спайк: Яндекс Музыка (SPEC §6.1)

Дата: 2026-10-29. Библиотека `yandex-music` 3.2.2 (async-клиент). Аккаунт владельца с Плюсом.
Запросы шли с IP в Нидерландах (AS216253) — это заодно проверка «сервер вне России».
Скрипты: [`scripts/spike_yandex.py`](../scripts/spike_yandex.py) (`auth`, `run`, `recheck`, `links`),
[`scripts/spike_audio_browser.mjs`](../scripts/spike_audio_browser.mjs) (воспроизведение в браузерах).
Сырые результаты — в `scripts/.spike-out/` (в .gitignore: там подписанные ссылки).

## Итог одной строкой
Всё, что нужно продукту, работает: Device Flow, поиск, метаданные, **незашифрованные** прямые ссылки
(AAC в MP4 / MP3, 192 кбит/с), которые играют напрямую в `<audio>` во всех проверенных браузерах с
перемоткой. Режим `direct` — основной, `proxy` — запасной на случай привязки ссылок к IP.

## 1. Авторизация (Device Flow)
| Вопрос | Ответ |
|---|---|
| Поддержка в библиотеке | Да: `request_device_code()` + `poll_device_token()` (и блокирующий `device_auth()`), client_id/secret официального Android-приложения |
| UX | Код из 8 символов (`lr3kt2gb`), страница **`https://ya.ru/device`**, код живёт **300 с**, интервал опроса **5 с** |
| Время до входа на практике | 141 с (первая попытка, с поиском страницы) |
| Токен | `expires_in = 31 536 000` (1 год), **есть `refresh_token`** |
| Подвох | Код привязывается к аккаунту, залогиненному в браузере. Владелец сначала подтвердил вход не тем аккаунтом (без Плюса). → В UI явно писать «войдите в аккаунт с Плюсом» и показывать, каким аккаунтом выполнен вход, с кнопкой «Это не я — войти другим» |
| Проверка Плюса | `client.me.plus.has_plus` после `init()` |
| Протухший/неверный токен | `UnauthorizedError` при `init()` / любом запросе |

## 2. Ссылки на аудио
Два метода:

**`get-file-info` (новый, `tracks_file_info`)** — используем его.
- Подписанный запрос (`sign` + `ts`), заголовок `X-Yandex-Music-Client` — всё делает библиотека.
- `transport=raw` → **незашифрованный файл** (проверено по магическим байтам: `ftyp isom` для
  AAC-MP4, MPEG-фрейм для MP3). `transport=encraw` → AES-128-CTR (ключ в ответе) — **не используем**.
- Для всех проверенных треков (6 шт.) при любом `quality` (`lossless`/`hq`/`nq`) сервер вернул
  **`aac-mp4` 192 кбит/с**; если исключить AAC из списка кодеков — `mp3` 192. FLAC не вернулся ни разу,
  даже при явном запросе (вероятно, ограничение аккаунта/региона) — нам он и не нужен.
- В ответе **4 зеркала** (`urls[]`, хосты `strm-*.strm.yandex.net`) — можно переключаться при ошибке
  без нового запроса к API.
- Без Плюса / анонимно: `quality: "preview"`, 30-секундный `preview.mp3` — **так и детектируем
  «нужна подписка»** (а не по исключению).
- Несуществующий трек: `BadRequestError` (на коротких id иногда возвращается чужой файл — id треков
  берём только из ответов API, не из ввода пользователя без проверки через `tracks()`).

**`download-info` + `get_direct_link` (старый)** — запасной.
- Только `mp3` 192 (без превью), ссылка `api.music.yandex.net/get-mp3/...`, `get_direct_link`
  нужно вызвать в течение минуты после `download-info`.
- **Отвечает 403, если в запросе есть заголовок `Origin`** (браузер не шлёт Origin для `<audio>` без
  `crossOrigin`, поэтому в браузере играет).

### Свойства ссылок `strm.yandex.net`
| Вопрос | Ответ |
|---|---|
| Range / перемотка | Да, `206 Partial Content`, `Content-Range` корректный (хотя `Accept-Ranges` не отдаётся) |
| Content-Type | `application/octet-stream` (браузеры сниффят контейнер; см. риск по Safari ниже) |
| CORS | Отдаёт `Access-Control-Allow-Origin: <origin>` (эхо). Для `<audio>` без `crossOrigin` не нужно |
| Привязка к User-Agent | **Нет** (Chrome UA и `curl` UA — оба 206) |
| Привязка к IP | **Не проверено** — у меня один исходящий IP. В подписи нет явного IP-параметра (`ysign1=…,lid=…,secret_version=…,source=mds,ts=…`), но хеш может его включать. Проверка — в ручном QA фазы 2 (сервер в РФ, браузер у владельца). Если привязка есть — `AUDIO_MODE=proxy` |
| Время жизни | В ссылке `ts=<hex epoch>` ≈ **время выдачи + ~250 ч**. Фактическую жизнь подтверждаю фоновой перепроверкой раз в 20 мин (результат — ниже). В любом случае клиент переполучает ссылку при ошибке воспроизведения |

### Воспроизведение в браузере
Страница с `http://localhost:5199` (Origin/Referer как у нашего фронта), `new Audio(url)`:
загрузка → `canplaythrough` → `play()` 1.5 с → seek на 60 с.

| Браузер | без `crossOrigin` | с `crossOrigin="anonymous"` |
|---|---|---|
| Chromium (Playwright) | ✅ играет, seek ✅ (`loadedmetadata` 5–110 мс) | ❌ |
| Google Chrome | ✅ / ✅ | ❌ |
| Microsoft Edge | ✅ / ✅ | ❌ |
| Firefox (Playwright) | ✅ / ✅ | ✅ для `strm`, ❌ для `get-mp3` |
| Safari macOS / iOS | не проверено (нет устройства) | — |

Вывод: **`<audio>` без `crossOrigin`**. Web Audio (`createMediaElementSource`) к такому элементу не
подключаем — для синхронизации он и не нужен: `outputLatency` берём из отдельного `AudioContext`.

## 3. Метаданные
| Что | Метод | Время | Результат |
|---|---|---|---|
| Поиск | `search(text)` | 375–670 мс | лучший результат + секции; транслит «радиохед» → артист Radiohead; работает и анонимно |
| Трек(и) | `tracks(ids)` | ~100 мс | батчем; `available`, `duration_ms`, `albums[0].id` |
| Альбом | `albums_with_tracks(id)` | ~110 мс | `volumes` (диски) → треки |
| Плейлист owner/kind | `users_playlists(kind, uid)` | ~95 мс | `tracks[].track` — полные треки |
| Плейлист по UUID | `playlist(uuid)` | ~140 мс | UUID вида **`ar.273c2610-…`** (префикс + UUID); тот же плейлист, что по owner/kind |
| Плейлисты пользователя | `users_playlists_list()` | ~125 мс | у владельца 0 — метод работает |
| «Мне нравится» | `users_likes_tracks()` | ~65 мс | `TrackShort` → догружать `tracks(ids)` пачками по 100 |
| Альбомы коллекции | `users_likes_albums()` | ~110 мс | ок |
| Артист | `artists_brief_info` (10 популярных) / `artists_tracks` (пагинация, всего 185) / `artists_direct_albums` | ~375 мс | ок |

### Обложки
`cover_uri` / `og_image` без схемы с `%%` вместо размера:
`avatars.yandex.net/get-music-content/10703962/da0bc4c9.a.3389005-2/%%` →
`https://avatars.yandex.net/get-music-content/…/400x400`. Для плейлистов — `cover.uri`.
Используем размеры `50x50`, `200x200`, `400x400`, `1000x1000`. Аватар пользователя:
`https://avatars.yandex.net/get-yapic/{avatarId}/islands-200`.

## 4. Форматы ссылок (веб, все отвечают 200 без редиректов)
- трек: `music.yandex.ru/album/{albumId}/track/{trackId}`, `music.yandex.ru/track/{trackId}`
- **«Поделиться» из мобильного приложения** (4 реальные ссылки владельца):
  `https://music.yandex.ru/album/3135476/track/26360014?ref_id=1F79053F-…&utm_medium=copy_link`
- альбом: `music.yandex.ru/album/{albumId}`
- плейлист: `music.yandex.ru/users/{login}/playlists/{kind}`, **`music.yandex.ru/playlists/{prefix}.{uuid}`**
- артист: `music.yandex.ru/artist/{artistId}`
- домены `.ru/.com/.by/.kz/.uz` — все живые; query/якоря не мешают.

## 5. География и прокси
- Из NL (не РФ) с аккаунтом Плюс всё работает: поиск, полные треки, ссылки, воспроизведение.
  VPS будет в России — основной сценарий, проблем не ожидается.
- Прокси: библиотека пробрасывает `proxy_url` в aiohttp (HTTP/HTTPS-прокси нативно;
  SOCKS — через `aiohttp-socks`). Прокси у владельца нет → **с реальным прокси не проверено**;
  реализуем `YM_PROXY_URL` и покроем тестом конфигурации.

## 6. Риски
1. **Привязка ссылок к IP** (не проверено) → есть режим `proxy`; проверка в ручном QA фазы 2.
2. **Safari и `application/octet-stream`** — Safari иногда строже к MIME. Проверка вручную; в `proxy`
   выставляем правильный `Content-Type` (`audio/mp4` / `audio/mpeg`).
3. Неофициальный API: смена подписи `get-file-info` сломает и библиотеку → фоллбэк на `download-info`.
4. Учётка Android-клиента для Device Flow — чужой client_id; если Яндекс его ограничит, останется вход по токену.

## 7. Время жизни ссылок (фоновая перепроверка)
Фоновая перепроверка сохранённых ссылок раз в 20 минут: ссылки `strm.yandex.net` (`get-file-info`)
отвечали `206` всю проверку — **2 ч 44 мин** (9 замеров); параметр `ts` в подписи обещает ~10 суток.
Старые `get-mp3` в этой проверке отвечают 403 только потому, что скрипт шлёт `Origin` (браузер для
`<audio>` его не шлёт и играет их). Вывод: ссылка живёт дольше любого трека; на случай протухания
клиент при ошибке берёт следующее зеркало, затем свежую ссылку.
