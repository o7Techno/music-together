# Известные проблемы и ограничения

Критичных известных багов нет. Некритичное и непроверенное:

| # | Что | Влияние | Что делать |
|---|---|---|---|
| 1 | Не проверено, привязаны ли ссылки Яндекса на аудио к IP запросившего (в спайке был один исходящий IP) | Если привязаны — в режиме `direct` с сервера в ДЦ трек не будет играть у слушателей | `AUDIO_MODE=proxy`; проверка — docs/manual-qa.md §2 |
| 2 | Safari (macOS/iOS) не проверен на реальном устройстве; ссылки Яндекса отдаются как `application/octet-stream` | Возможна несовместимость с Safari в режиме `direct` | Ручной QA; при проблеме — `AUDIO_MODE=proxy` (там правильный `Content-Type`) |
| 3 | Профили коррекции синхрона для iOS/Android — исходная гипотеза (шире мёртвая зона, мягче темп) | На телефонах точность может отличаться от целей §5.1 | Подбор по отладочной панели (`?debug=1`), переопределение `?syncProfile=` |
| 4 | Компенсация задержки вывода звука по умолчанию выключена (DECISIONS D-021) | Возможен постоянный сдвиг между разными браузерами/устройствами на десятки мс | Проверка «на слух» на FakeProvider, переключатель в отладочной панели |
| 5 | Device Flow использует client_id официального Android-приложения | Если Яндекс ограничит его — вход по коду перестанет работать | Запасной вход по токену уже есть |
| 6 | SOCKS-прокси для Яндекса не поддерживается | Только для серверов вне РФ | HTTP(S)-прокси (D-026) |
| 7 | Lossless (FLAC) не используется | Качество — AAC/MP3 192 кбит/с | Сознательно: совместимость с браузерами (D-007) |
| 8 | E2E-тесты синхрона меряют `currentTime` медиаэлемента, а не реальный звук | Задержки звукового тракта устройств не учтены в цифрах | Ручная проверка «на слух» |
| 9 | Демон Docker на машине разработки не отвечал во время фазы 5 | Сборка образов и `docker compose up` проверены только в CI (job `docker`) | — |
