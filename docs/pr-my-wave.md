# Моя волна, лайки и плейлисты

Первая часть `SPEC-wave.md`: лайки, плейлисты, волна участника, волна по зерну и настройки волны. Общая волна —
следующим PR (`feature/shared-wave`, D-040).

## Что сделано
- **Волна в комнате.** Кнопка «Включить мою волну» или запуск по зерну: текущий трек, исполнитель, альбом,
  настроение, занятие, жанр. Вся комната слушает синхронно, каждый своим токеном.
- **Сочетание с очередью.** Ручные треки играют первыми; в настройках комнаты есть режим «через один». Секция
  «Дальше в волне» с действиями «закрепить» и «убрать».
- **Обратная связь.** Сервер сам сообщает о старте, дослушивании и пропуске с реально сыгранным временем. Есть
  «Не нравится» и настройка «Не учить мою волну». Пока владельца нет в комнате, фидбек не отправляется.
- **Лайки и плейлисты.** ♥, `L`, добавление в плейлист, создание приватного плейлиста, вопрос про дубликат,
  сохранение очереди и истории. Действуют только на аккаунт нажавшего.
- **Сбои.** Окно 15 минут после ухода владельца переживает рестарт; выход из аккаунта, бан и потеря токена
  останавливают волну сразу; при отказе Яндекса — повторы и автовосстановление; потерянная сессия создаётся заново.

## Как устроено
- `rooms/wave.py` — чистая логика; `rooms/room.py` вызывает её в переходах; `rooms/wave_driver.py` ходит в Яндекс в
  фоне, вне `room.lock` и цикла чтения WebSocket. Поздние ответы отбрасываются по `generation`.
- Следующий трек определяет сервер и присылает в `wave.nextTrackId`, по нему клиент предзагружает. Изменения волны
  не меняют `playback.version`, поэтому не сбрасывают коррекцию дрейфа.
- Решения: D-040–D-043, поведение API — `docs/wave-spike.md`.

## Как проверить
```bash
npm run check
npm run e2e
```
Вручную без аккаунта: `npm run dev:fake`, две вкладки, вкладка «Волна» → «Включить мою волну». На реальных
аккаунтах — `docs/manual-qa.md` §6. Методы провайдера на настоящем API: `scripts/spike_wave.py provider`.

## Результаты
- Backend: 213 тестов, ruff, mypy. Frontend: 64 теста Vitest, eslint, tsc.
- E2E локально: все сценарии, включая новый переход между треками волны в `sync.spec.ts`.
- Настоящий API: спайк и прогон методов провайдера. **В браузере на реальном аккаунте волна не проверялась.**
- CI запускается при открытии PR и пока не проверен.
- Скриншоты и гиф не приложены: снимать нужно на реальном аккаунте.

## Настройки
`WAVE_OWNER_GRACE_S=900` — необязательно, значение по умолчанию такое же.

## Риски
- **Откат кода** после релиза теряет очередь в активных комнатах: `ApiModel` запрещает лишние поля. Перед деплоем —
  `scripts/backup.sh`.
- **Аккаунт.** Волна добавляет автоматическую активность через неофициальный API с IP сервера. Реакция Яндекса
  неизвестна; запросы идут только при слушателях в комнате.
- **Лимит пропусков.** API сообщает 6 в час, но 10 подряд приняты. Сверх лимита может перестать доходить только фидбек.
- **Не измерено:** насколько волна реагирует на пропуски, влияние настроек, поведение на больших коллекциях.
