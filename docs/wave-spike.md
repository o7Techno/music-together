# Спайк: «Моя волна», лайки и плейлисты (SPEC-wave §2)

Дата: 2026-10-31. `yandex-music` 3.2.2, один аккаунт владельца с Плюсом, запросы с компьютера разработки.
Скрипт: [`scripts/spike_wave.py`](../scripts/spike_wave.py) (`read`, `collection`, `skip-limit`, `session-age`).
Сырые отчёты — в `scripts/.spike-out/` (в .gitignore).

## Итог
Выбран **сессионный API ротора**. Сессия, порции, все нужные события, зёрна, настройки, лайки и плейлисты
работают. Треки волны получают аудио тем же способом, что и обычные. Классический API тоже отвечает и
остаётся запасным, отдельную реализацию не делаем.

## Что проверено

### Волна
| Вопрос | Ответ |
|---|---|
| Создание сессии | `rotor_session_new("user:onyourwave")`, около 350 мс, есть `radio_session_id` и `batch_id` |
| Порция | **5 треков**, 280–400 мс, у каждой своя `batch_id` |
| Повторы | С `queue` — 0 повторов за 5 порций. **С пустым `queue` — 4 из 5 повторов**: параметр обязателен |
| Содержимое | За 25+ треков только `type=track`; рекламы, `None`, недоступных и треков без альбома не встретилось. Фильтры оставляем как защиту |
| Длительность | 149–352 с, `duration_ms` везде есть |
| Аудио | `tracks_file_info` для 6 треков волны: `aac-mp4`, `raw`, без ключа, 4 зеркала. При запросе `hq` API вернул `quality=nq` |
| Несуществующая сессия | `rotor_session_tracks` без ошибки, `unknown_session=true`. Фидбек в такую сессию — **HTTP 400** |
| Без фидбека | Запрос порций работает, ошибок нет. Влияние на качество не измерено |

### События
Все приняты: `radioStarted`, `trackStarted`, `skip`, `trackFinished`, `like`, `unlike`, `dislike`, `undislike`,
пачка `rotor_session_feedbacks`, фидбек внутри `rotor_session_tracks(feedbacks=…)`. `batch_id` не обязателен
(`trackStarted` без него принят), но передаём. Отправляем пачкой или вместе с запросом порции.

### Лимит пропусков
`rotor_account_status` отдаёт `skips_per_hour: 6`. **Отправка 10 `skip` за несколько секунд в инкогнито-сессии
принята полностью**, значение не изменилось, сессия не завершилась, новые порции приходят, `skipFailed` не
встретился. Проверено только так: в обычной сессии и на длинном интервале лимит мог бы вести себя иначе.
Вывод: кнопка «Следующий» лимит не проверяет; ошибку отправки `skip` только логируем.

### Зёрна
Приняты и выдают 5 треков: `genre:rock`, `mood:happy`, `activity:workout`, `track:{id}`, `artist:{id}`,
`album:{id}`. Список станций — 701 (`rotor_stations_list`): `genre`, `micro-genre`, `mood` (18), `activity` (12),
`epoch` (9), `personal`, `editorial`, `tempo`, `local-language`, `mix-by-*`, `author`.
Для панели хватит `mood` и `activity` (короткие списки) и `genre`. Контексты из `rotor_wave_settings`:
`genre:dance`, `activity:wake-up`, `activity:road-trip`, `activity:work-background`, `activity:workout`,
`mood:relaxed`, `activity:fall-asleep`.

### Настройки
Передаются сидами рядом с `user:onyourwave`:
- `settingLanguage`: `russian`, `not-russian`, `without-words`, `any`;
- `settingDiversity`: `favorite`, `discover`, `popular`, `default`;
- `settingMoodEnergy`: `active`, `fun`, `calm`, `sad`, `all`.

Конкретные значения приняты в `accepted_seeds`; значения `any` и `default` (вероятно, и `all`) означают «по умолчанию»
и в `accepted_seeds` не попадают. **Что настройка заметно меняет выдачу, не доказано**: пересечение с первой
порцией 0–0,25, но столько же даёт и новая сессия без настроек (`default` — 0, инкогнито и классический API — 0,25).
Проверить на слух при ручной проверке.

### Инкогнито
`rotor_session_new(..., incognito=True)` работает, фидбек принимается. Не учит ли он волну, ответы API показать
не могут. Решение для «не учить мою волну»: инкогнито-сессия **и** никакого фидбека.

### Лайки
| Что | Ответ |
|---|---|
| `users_likes_tracks_add/remove` с `user_id` | Работают; повторный лайк идемпотентен; лайк сразу виден в `users_likes_tracks`, 96–128 мс |
| `users_dislikes_tracks_add/remove` | Работают, видны сразу |
| Пакетный статус | Нет: только полный список; у `Sequence` есть готовый `liked` |

### Плейлисты
| Что | Ответ |
|---|---|
| Создание | `visibility="private"` применилось, стартовая ревизия 1 |
| Вставка | Каждое изменение увеличивает `revision` на 1 |
| **Устаревшая ревизия** | **HTTP 412**, тело `{"error":{"name":"wrong-revision","message":"Expected revision: 1, actual revision: 2"}}`. В библиотеке это `NetworkError`, `_call` повторил бы его с той же ревизией |
| Несуществующий плейлист | Тоже **412 `wrong-revision`** («actual revision: 0»). Различается только перечитыванием: `users_playlists` |
| Дубликат | API **принимает молча** — проверка только на нашей стороне |
| Пачка | `Difference.add_insert(at, [9 треков])` одной операцией — 11 треков в плейлисте |
| Удаление | `delete_track(kind, 0, 1, revision)` удаляет один трек: `to` не включается |
| `album_id` пустой | **HTTP 400 `wrong-json`**: альбом обязателен, из `BadRequestError` получится `ProviderNotFoundError` |

## Что не проверено
- Сколько живёт сессия без запросов: результат фоновой проверки — ниже.
- Большая коллекция: на этом аккаунте 0 лайков и 0 плейлистов, поэтому `users_playlists([kinds])` не вызывался, а
  время `users_likes_tracks` на тысячах треков неизвестно.
- Реакция рекомендаций на фидбек и качество выдачи: нужна ручная проверка.
- Лимит размера плейлиста и одного `diff` (проверено 9 треков). Берём порции по 100 и снижаем при ошибке.
- Код ответа 403: ни разу не встретился.
- Второй аккаунт: трек из волны первого аккаунта у второго не проигрывался.
- Служебный «Мне нравится» в списке плейлистов: на пустой коллекции он не появился.

## Побочные эффекты на аккаунте
В волну владельца отправлены 1 `radioStarted`, 2 `trackStarted`, 1 `skip` с `from=web-spike`. Остальные события —
в инкогнито-сессиях. Лайки и дизлайки возвращены к исходному состоянию (проверено сравнением), временный приватный
плейлист удалён (проверено списком).
