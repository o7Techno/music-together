# Слушаем вместе

Веб-сервис для совместного прослушивания Яндекс Музыки: друзья заходят в общую комнату и **синхронно,
секунда в секунду** слушают один трек. Очередь общая, любой может добавлять треки, ставить на паузу,
перематывать и пропускать.

- Каждый слушает **со своего аккаунта с Плюсом**: сервер синхронизирует только состояние (трек,
  позиция, пауза, очередь), а не звук. Ссылка на аудио получается токеном самого слушателя и
  отдаётся только ему.
- Рассинхрон между браузерами — **~10 мс медиана, ~20 мс p95** (e2e на трёх клиентах,
  [docs/sync-measurements.md](docs/sync-measurements.md)).
- Добавление треков: поиск с клавиатурой, Ctrl+V ссылки в любом месте страницы, перетаскивание ссылки,
  альбомы, плейлисты, «Мне нравится» с выбором треков.
- Десктоп и телефон, тёмная и светлая темы, экран блокировки (Media Session), чат и реакции.

## Быстрый старт локально (без аккаунта Яндекса)

Нужны: Node 24+, Python 3.12, [uv](https://docs.astral.sh/uv/), ffmpeg (для тестовых треков),
Docker (для Postgres; без него можно на SQLite — см. ниже).

```bash
npm run setup                     # uv sync + npm ci
python scripts/gen_fake_audio.py  # тестовые треки со щелчками раз в секунду
npm run dev                       # Postgres в docker + бэкенд :8000 + фронт :5173
```

Откройте http://localhost:5173, войдите под любым именем (режим разработки, FakeProvider), создайте
комнату и откройте её ещё во второй вкладке — щелчки должны звучать как один.

С реальной Яндекс Музыкой локально: создайте `.env` в корне с
`MUSIC_PROVIDER=yandex`, `TOKEN_ENCRYPTION_KEYS=<ключ>` (команда генерации — в `.env.example`) и
`ENV=dev`, `PUBLIC_ORIGIN=http://localhost:5173`.

## Деплой на VPS (≈15 минут)

Подойдёт любой VPS с Ubuntu 22.04+/Debian 12, 1 ГБ RAM. Рекомендуется сервер **в России**
(Яндекс Музыка, см. [docs/yandex-spike.md](docs/yandex-spike.md)).

1. **DNS.** A-запись домена (например, `music.example.com`) → IP сервера. Порты 80 и 443 открыты.
2. **Docker.**
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. **Код и конфигурация.**
   ```bash
   git clone https://github.com/o7Techno/music-together.git && cd music-together
   ./scripts/init-env.sh music.example.com   # .env со случайными секретами
   ```
   Остальное в `.env` можно не трогать: провайдер — Яндекс, режим аудио — `direct`.
4. **Запуск.**
   ```bash
   docker compose up -d
   docker compose ps          # все сервисы running/healthy
   ```
   Caddy сам получит сертификат. Откройте `https://<домен>` и войдите через Яндекс.
5. **Проверка ссылок на аудио.** Если трек не играет ни у кого (ошибка загрузки), ссылки Яндекса
   привязаны к IP сервера — поставьте `AUDIO_MODE=proxy` в `.env` и `docker compose up -d`.
   Подробности и ручной чек-лист — [docs/manual-qa.md](docs/manual-qa.md).

Обновление: `git pull && docker compose up -d --build`. Бэкапы и восстановление —
[docs/operations.md](docs/operations.md).

## Переменные окружения

Все — в [`.env.example`](.env.example) с комментариями. Главные:

| Переменная | Назначение |
|---|---|
| `DOMAIN` | домен; HTTPS-сертификат Caddy получает и продлевает сам (Let's Encrypt) |
| `PUBLIC_ORIGIN` | origin фронта для проверки Origin (CSRF, WebSocket) |
| `SESSION_SECRET` | секрет сессий (≥ 32 символов) |
| `TOKEN_ENCRYPTION_KEYS` | ключи Fernet для токенов Яндекса; несколько через запятую — ротация |
| `POSTGRES_PASSWORD` | пароль БД в docker compose |
| `MUSIC_PROVIDER` | `yandex` или `fake` (демо без аккаунтов, вход без Яндекса) |
| `AUDIO_MODE` | `direct` (браузер играет ссылку Яндекса) или `proxy` (поток через сервер) |
| `YM_PROXY_URL` | HTTP(S)-прокси для запросов к Яндексу (если сервер вне РФ) |
| `SENTRY_DSN`, `SENTRY_FRONTEND_DSN` | необязательный Sentry для бэка и фронта |

## Как устроена синхронизация

```
            ┌──────────── сервер (авторитетное состояние комнаты) ────────────┐
            │ PlaybackState { trackId, status, positionMs, anchorServerMs, v } │
            └──────▲───────────────┬─────────────────────────────▲─────────────┘
         ping/pong │      playback │ (новое состояние, version+1)  │ ready{v}, drift
                   │               ▼                               │
   клиент: offset часов ── ожидаемая позиция = positionMs + (serverNow − anchor)
                   │               │
                   ▼               ▼
            <audio> своего аккаунта: старт точно в момент anchor, затем коррекция дрейфа
```

1. **Часы.** Клиент делает 8 пингов и берёт медиану offset по трём замерам с наименьшим RTT,
   повторяет каждые 30 с.
2. **Старт с барьером.** При смене трека сервер переводит комнату в `loading`. Каждый клиент
   загружает трек своим токеном и отвечает `ready`. Сервер ждёт всех, но не дольше 2.5 с, и назначает
   старт **в будущем** (`now + 300 мс`). Клиенты запускают трек точно в этот момент: таймер плюс
   доводка короткой паузой в цикле.
3. **Коррекция дрейфа** каждые 250 мс: до 20 мс — ничего не делаем; до 1 с — плавно меняем
   `playbackRate` в пределах ±5 %; дальше — жёсткий seek с упреждением, не чаще раза в 2 с.
4. **Надёжность.** Команды применяются последовательно, каждое изменение увеличивает `version`.
   «Следующий» и перемотка несут id текущего трека, поэтому двойное нажатие не пропустит два трека.
   Окончание трека отслеживает сервер, а не клиенты. Следующий трек предзагружается за 20 с.

Подробнее — SPEC §5 и код [frontend/src/player](frontend/src/player) (чистый TypeScript, покрыт
unit-тестами) и [backend/app/rooms](backend/app/rooms).

## Волна, лайки и плейлисты

Любой участник с Плюсом включает волну в панели «Волна»: своя или по зерну (текущий трек, исполнитель,
альбом, настроение, занятие, жанр). В общей волне треки участников идут по очереди, и каждый решает, участвует ли его волна. Треки запрашиваются токеном владельца волны, а слушает каждый своим.
Ручные треки играют первыми; режим «через один» включается в настройках комнаты. Волна учится на том, что
дослушивает и пропускает комната, а переключатель «Не учить мою волну» это отключает. Если владелец ушёл, волна
играет ещё 15 минут (`WAVE_OWNER_GRACE_S`). ♥ и добавление в плейлист действуют только на аккаунт того, кто нажал.
Подробности — `SPEC-wave.md`, поведение API Яндекса — `docs/wave-spike.md`.

## Известные ограничения

- Неофициальный API Яндекс Музыки (библиотека `yandex-music`): изменения на стороне Яндекса могут
  временно сломать вход или воспроизведение. Вся интеграция — в одном модуле
  (`backend/app/providers/yandex.py`).
- Нужна подписка Плюс у каждого слушателя; без неё — понятное сообщение, звук не играет.
- Треки, недоступные в регионе/для аккаунта конкретного участника, у него не играют (остальные слушают).
- SOCKS-прокси для Яндекса не поддерживается (только HTTP/HTTPS).
- Один инстанс бэкенда (состояние комнат в памяти процесса), ориентир — 20 комнат × 10 человек.
- Полный список — [docs/known-issues.md](docs/known-issues.md).

**Идеи на будущее:** «Моя волна» как источник очереди, голосование за следующий трек, тексты песен.
